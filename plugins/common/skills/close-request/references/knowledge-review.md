# Knowledge review when closing

Every close includes a short review so the next piece of work starts smarter.

1. Read the final README, `insights.md` and outputs.
2. List durable learnings, for example: a metric rule validated or changed, a source of
   truth discovered, a divergence explained, a join or column trap, a process or access
   step, a dashboard behaviour.
3. For each one decide: do not record, update an existing article, or create a new one.
   Skill `knowledge-base` decides where and how; skill `metric-card` owns any metric
   definition or status change.
4. Update the knowledge index when an article is created, moved or renamed.
5. Publish outside the repository only after the change is merged to the main branch, and
   only with approval.
6. Record in the README which articles changed, or why nothing was added.

Do not record ephemeral operational noise. Record what would save time in the next analysis.
