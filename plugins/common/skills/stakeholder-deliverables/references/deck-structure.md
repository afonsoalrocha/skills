# Deck structure

How to organise a stakeholder deck. Use the team's template for the look; this is the
order and the content rules.

## Order

1. Cover.
2. Section divider: overview.
3. **Key numbers first**: a KPI slide right after the cover, at most 4 cards, each with
   label, value and one line of context.
4. Section divider: detailed analysis.
5. Tables and charts.
6. Section divider: insights and recommendations.
7. Insights as short bullets.
8. **Close with recommendations** or next steps (two columns work well: finding on the
   left, action on the right).

## Rules

- Split the deck into sections with divider slides; one idea per slide.
- Keep tables to 10 to 12 rows. A longer table is split or summarised, with the full data
  in an attachment.
- Generate the chart first (an image file from a plotting library), then insert it as an
  image slide. Check the image alone before placing it.
- Put the data source in the slide note or footer of every slide that shows numbers: system
  or report name and extraction date.
- State partial or blocked results on the slide, not only in the message that carries it.
- Slide titles state the conclusion ("Conversion fell in week 3"), not the topic.
- Save the deck next to the script that built it, and render every slide to an image for
  review (`references/pdf-qa.md` applies to a deck exported as PDF).
- Keep the speaker view free of anything you would not show the audience.
